İnşaat ERP backend için HTTPS adresi (ör. https://insaat-erp-api.onrender.com) almak — kısa yol: Render.com

1) GitHub’da insaat-erp (veya bu backend’i içeren) repo’yu hazırlayın; kökte render.yaml + insaat-erp-backend/ klasörü olsun.

2) https://render.com — kayıt / giriş — “New” → “Blueprint” → repo seçin → render.yaml onaylansın.

3) Render panosunda servise girin → Environment:
   - DATABASE_URL = Render PostgreSQL oluşturup “External Database URL” yapıştırın (veya Internal + aynı VPC; genelde External URL yeterli).
   - JWT_SECRET = uzun rastgele bir metin (üretici kullanın).

4) Deploy bitince üstte görünen URL örnektir:
   https://insaat-erp-api.onrender.com
   Bu metnin SONUNA /api/v1 EKLEMEYİN. FinSkor Netlify’da:
   INSAAT_ERP_API_URL = https://insaat-erp-api.onrender.com

5) Tarayıcıda test: https://…onrender.com/health

Not: Ücretsiz Web “uyku” moduna geçer; ilk istek 30–60 sn sürebilir. Üretim için ücretli plan veya sabit sunucu düşünün.

--- Supabase ile ne olur, ne olmaz? ---

Supabase hesabınızı şu şekilde KULLANABİLİRSİNİZ:
  • Sadece VERİTABANI: Supabase → Project → Settings → Database → “Connection string” (URI, genelde “Transaction” veya “Session” pooler). Bunu Render’daki (veya başka bir yerdeki) Node backend’in ortam değişkeni DATABASE_URL olarak yapıştırın. Kod tarafında DATABASE_URL zaten destekleniyor.

Supabase TEK BAŞINA Render’ın yerini ALMAZ:
  • Supabase, sizin Express + /api/v1 + Socket.io backend’inizi “olduğu gibi” host etmez. API sunucusu yine bir yerde çalışmalı (Render, Fly.io, küçük VPS…).
  • FinSkor’daki INSAAT_ERP_API_URL hâlâ o Node API’nin HTTPS kök adresidir; Supabase proje URL’si (xxx.supabase.co) bunun yerine geçmez.

Özet: Supabase = çoğu senaryoda PostgreSQL (ve isterseniz ileride Auth/Storage). “Render yerine sadece Supabase” = veriyi Supabase’e taşırsınız, API’yi yine başka bir host’ta çalıştırırsınız.
